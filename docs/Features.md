# Telegram conversation features

This is a deliberately small first map of the Telegram Bot API, focused on the
basic building blocks of a conversation.

## Current scope and decisions

- **Chat scope: private chats only**
  - For now, a conversation means a one-to-one chat between one user and the bot.
  - A bot cannot initiate a private conversation: the user must contact or start
    the bot first.
  - Groups, supergroups, channels, forum topics, group privacy mode, and chat
    administration are outside the current scope.
- **Update delivery: webhook only**
  - The bot will register an HTTPS endpoint using `setWebhook`.
  - Telegram will send each incoming `Update` to that endpoint as an HTTPS POST
    request containing JSON.
  - Long polling with `getUpdates` is outside the current scope.
- **Deferred features**
  - Payments, Mini Apps, inline mode, games, and Telegram Business features can
    come later.

## Message types

- **Text** (sending / receiving)
  - Text can contain entities such as bold, italic, links, mentions, hashtags,
    bot commands, code, and spoilers.
  - A URL may generate a configurable link preview.
  - Telegram also supports **rich messages** made from structured blocks such as
    headings, lists, tables, quotations, and media. This is an advanced format to
    explore later.
- **Photo** (sending / receiving)
  - Telegram exposes several generated sizes of the same photo.
  - A photo can have a caption and a media spoiler.
- **Document / file** (sending / receiving)
  - Use this for a general file that should preserve its filename and MIME type.
  - This is distinct from sending the same image as a compressed/displayed photo.
- **Voice note** (sending / receiving)
  - A short recording displayed with Telegram's voice-message interface.
- **Audio / music** (sending / receiving)
  - An audio file displayed in the music player, with metadata such as performer
    and title. It is distinct from a voice note.
- **Video** (sending / receiving)
- **Video note** (sending / receiving)
  - The short, round video-message format. It is distinct from a normal video.
- **Animation / GIF** (sending / receiving)
  - Telegram represents animated GIF-style content as an `animation` (usually an
    MPEG-4 file), not as a photo.
- **Sticker** (sending / receiving)
  - Stickers may be static, animated, or video stickers.
- **Contact** (sending / receiving)
- **Location and venue** (sending / receiving)
  - A location is geographic coordinates; a venue adds a name and address.
  - A location can optionally be **live**, allowing the coordinates to update for
    a defined period while keeping the same message.
- **Poll / quiz** (sending / receiving)
  - Poll answers can arrive as separate updates in the cases supported by the API.
- **Dice** (sending / receiving)
  - A Telegram-native animated emoji whose random result is generated by Telegram.
  - Despite the name, it also supports animations such as darts, basketball,
    football, bowling, and a slot machine.

Most media messages can also carry a **caption**. Telegram gives the bot a
`file_id` for received files; the bot can reuse that ID later without uploading
the same file again.

## Message context

- **Reply to a specific message**
  - A reply may also quote a selected portion of the original text or caption.
- **Forwarded message**
  - A forwarded message may contain origin information, subject to Telegram's
    privacy rules.
- **Media group / album**
  - An album arrives as multiple messages that share the same `media_group_id`,
    rather than as one message containing a list of media.

## Conversation controls

- **Bot commands**
  - Slash commands such as `/start`, `/help`, and `/cancel` are text entities with
    special Telegram UI support and can be advertised in the bot's command menu.
- **Inline keyboard buttons**
  - Buttons are attached to a bot message. A callback button sends a
    `callback_query` update instead of posting another visible chat message.
- **Reply keyboard buttons**
  - These temporarily replace the user's keyboard with suggested responses. When
    selected, they normally send a regular message to the chat.
- **Reaction** (sending)
  - A reaction is associated with an existing message; it is not a message type.
  - The bot can apply one with `setMessageReaction`. Receiving reaction-change
    updates requires chat administration, so it is outside this private-chat scope.
- **Chat action / typing indicator**
  - The bot can briefly show states such as `typing`, `upload_photo`, or
    `record_voice` while preparing a response.

## Message lifecycle

- **Edited messages**
  - Incoming edits arrive as `edited_message` updates. Bots can also edit messages
    they sent, subject to the method's rules.
- **Deleted messages**
  - A bot can delete messages when the chat type, age of the message, and its
    permissions allow it. Ordinary deletions are not a general incoming update,
    so do not assume the bot will always be notified when a user deletes a message.
- **Streaming a response**
  - `sendMessageDraft` streams a temporary preview in a private chat while text is
    being generated. The preview lasts for 30 seconds; call `sendMessage` with the
    complete text to persist the final message.

## Receiving events

- Telegram delivers an **Update** envelope, which may contain a new message, an
  edited message, a callback query, a poll answer, and more.
- In this project, Telegram delivers those updates to the registered **webhook**.
- The endpoint should acknowledge a successfully received update with a `2xx`
  HTTPS response.

## Useful next boundary

After these private-conversation basics are familiar, the next layer can cover
forwarding/copying and file download details. Other chat types and their
permissions can remain a separate, later step.
